# v1.0.0 contract readiness

Use this after stabilization checks pass and before final release tagging.

## Contract surfaces

- CLI: frozen candidate. `scieqlint check`, `init`, `demo`, `explain`,
  `presets`, and `graph` are documented and CLI-tested.
- Public API: frozen candidate. `docs/api.md` documents `check_paths`,
  `check_documents`, `graph_paths`, `graph_documents`, `load_config`,
  `CheckResult`, and `Diagnostic`.
- JSON: frozen candidate. Result and diagnostic schemas are packaged and
  validated by golden tests.
- SARIF: frozen candidate. SARIF output is golden-tested, size-guarded, and
  documented for GitHub upload.
- Graph JSON: frozen candidate. Graph schema `0.3` is packaged, validated, and
  golden-tested.
- Config: frozen candidate. `docs/configuration.md` documents project mode,
  checks, presets, aliases, baselines, report visibility, and ignore rules.
- Diagnostics: frozen candidate. `docs/diagnostics.md` lists emitted and
  reserved codes, and catalog tests cover user-facing codes.
- Release checks: required. `python scripts/check_pack.py`, docs build,
  package CI, compatibility matrix, and stabilization tests must be green.

Stable-tag publication also runs the fail-closed gates in the stabilization
checklist only for stable semver tag pushes: source, wheel, source-distribution,
and tag version identity, at least 100 independently labeled semantic equations
executed through the public analysis path with their expected diagnostics and exit
status, the generated-formula quality corpus
with exact text/JSON goldens against both installed artifacts, and the fixed
100-document/500-equation/500-reference workload under three seconds. A documented
prerelease such as `v1.1.0rc1` is outside this stable publication workflow and does
not enter its exact-version or publish path.
The build job uploads the distribution once and carries its immutable artifact
ID through smoke into publication. Smoke and publish both download by that ID,
and the publish job does not rebuild or check out another source revision. The
stable release workflow wires separate clean wheel and source-distribution
installs and CLI smoke for each. Manual dispatch also runs the installed-artifact
accuracy, golden-output and performance checks without publishing. This is
workflow-wiring evidence, not stable-tag execution evidence. Stable-tag
execution is also fail-closed on provenance: the tagged commit must equal the
current protected `main` commit, and the tag and branch SHAs are rechecked after
artifact validation and immediately before publication. Release concurrency
cancels an older run for the same ref. Both build and publish require exactly one
wheel, exactly one source distribution, and no extra distribution files; download
digest mismatches are errors. Release build and test dependencies are constrained
by `.github/release-constraints.txt`, and the resolved versions are recorded in
each run's summary. Repository administrators must protect stable tags and require
approval for the `pypi` environment with administrator bypass disabled. These are
workflow-wiring and control requirements, not stable-tag execution evidence.
The corpus provides 102 source equations with independently justified expectations (39 positive and
63 negative), and ordinary PR CI enforces the 100-equation accuracy gate. Exact
release-artifact checks and stable-tag execution remain required before publication.
The current status is kept in
`docs/releases/v1.0.0-stabilization-checklist.md`.
