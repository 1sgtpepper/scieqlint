# v1.0.0 stabilization checklist

Use this checklist before stable contract readiness review.

## Required gates

- [x] Supported Python versions are declared in package metadata.
- [x] CI test matrix covers Python 3.11, 3.12, and 3.13.
- [x] JSON schema tests cover result and diagnostic schema shape.
- [x] Golden output tests validate JSON, text, GitHub, and SARIF output.
- [x] Diagnostic catalog tests cover user-facing diagnostic codes.
- [x] Accuracy benchmark fixtures are exercised by tests.
- [x] Representative project performance guard keeps file, math-block, and
      diagnostic counts linear.
- [x] Package CI builds wheel and sdist, checks metadata, runs the sdist test suite
      from an extracted tree, and runs the wheel CLI smoke in a clean venv.
- [x] Docs CI builds with `mkdocs build --strict`.

## Stable-tag release gates

The release workflow runs on stable semver tag pushes matching
`v[0-9]+.[0-9]+.[0-9]+` and blocks publication until these checks pass on the
same source, wheel, and source-distribution artifact. A documented prerelease
such as `v1.1.0rc1` is outside this stable workflow and is not published by it.
Manual dispatch runs the same installed-artifact accuracy, golden-output and
performance checks without publishing. Tag/main identity checks and publication
remain specific to stable tag pushes.

- [ ] Source, wheel, source-distribution, and tag versions agree.
- [ ] The generated-formula quality corpus matches its exact text and JSON goldens
      against both installed release artifacts.
- [ ] At least 100 independently labeled semantic equations execute through the
      public analysis path with their expected diagnostics and exit status.
- [ ] A fixed 100-document/500-equation/500-reference workload completes in
      under three seconds.

The current corpus contains 102 source equations with independently justified expectations (39 positive
and 63 negative). Ordinary PR CI enforces the 100-equation accuracy gate through the
public analysis path. The release workflow must still recheck that evidence against
the exact installed release artifacts; version identity, generated-formula goldens,
the performance budget and publication controls remain separate release gates.
The timed performance check remains skipped in ordinary PR CI.

Publication also requires repository controls and provenance checks: the stable tag must
be immutable and point to the current protected `main` commit, the `pypi` environment must
require approval with administrator bypass disabled, and the release workflow must pass its
final tag/branch SHA recheck. The workflow downloads one immutable artifact by ID with a
fatal digest-mismatch policy, rejects any distribution set other than one wheel plus one
source distribution, and uses the checked-in `.github/release-constraints.txt` pins while
recording resolved dependencies.

## Failure handling

Any failed stabilization gate must link a narrower follow-up issue before this
checklist is treated as complete. No new feature work belongs in this checklist.
