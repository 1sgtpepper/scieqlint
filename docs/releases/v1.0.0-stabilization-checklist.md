# v1.0.0 stabilization checklist

Use this checklist before stable contract readiness review.

## Required gates

- [x] Supported Python versions are declared in package metadata.
- [x] CI test matrix covers Python 3.11, 3.12, and 3.13.
- [x] JSON schema tests cover result and diagnostic schema shape.
- [x] Golden output tests validate JSON, text, GitHub, and SARIF output.
- [x] Diagnostic catalog tests cover user-facing diagnostic codes.
- [x] Accuracy benchmark fixtures are exercised by tests.
- [x] Representative project performance guard keeps file, math-block, and
      diagnostic counts linear.
- [x] Package CI builds wheel and sdist, checks metadata, installs both forms in
      clean venvs, and runs CLI smoke commands.
- [x] Docs CI builds with `mkdocs build --strict`.

## Stable-tag release gates

The release workflow blocks a stable `v*` tag until these checks pass on the
same source, wheel, and source-distribution artifact:

- [ ] Source, wheel, source-distribution, and tag versions agree.
- [ ] At least 100 independently labeled semantic equations execute through the
      public analysis path with their expected diagnostics and exit status.
- [ ] A fixed 100-document/500-equation/500-reference workload completes in
      under three seconds.

The current corpus contains no independently labeled equation evidence, so stable
publication is intentionally blocked until real licensed benchmark evidence is
added. Ordinary PR CI
keeps these release-only checks skipped; it still runs the underlying benchmark
and stabilization tests as ordinary tests.

## Failure handling

Any failed stabilization gate must link a narrower follow-up issue before this
checklist is treated as complete. No new feature work belongs in this checklist.
