# v1.1.0 release checklist

Use this checklist for the generated MyST/scientific-doc validation release.

## Completed release scope

- [x] MyST structure diagnostics for headings, fences, directives, roles, and
      code-cell metadata.
- [x] Heading hierarchy diagnostics for skipped levels and repeated top-level
      headings.
- [x] Generic MyST reference diagnostics for missing and ambiguous targets.
- [x] Generated-output anchor audit support for provenance-backed callers.
- [x] Packaged `generated-myst` scanner preset and GitHub annotation workflow
      docs; provenance checks remain explicit already-loaded-document policy.

## Required checks

- [x] Focused MyST, reference, generated-output, config, CLI, diagnostics, and

- [x] Full `pytest` suite.
- [x] `ruff format --check .` and `ruff check .`.
- [x] `python -m mkdocs build --strict`.
- [ ] GitHub CI, Docs, CodeQL, and Scorecard checks on the exact release head;
      refresh this evidence after promotion to protected `main`.

## Stable-tag release gates

The release workflow accepts only stable semver tag pushes matching
`v[0-9]+.[0-9]+.[0-9]+`. It requires source, wheel, source distribution, and tag
version identity, at least 100 independently labeled semantic equations executed
through the public analysis path with their expected diagnostics and exit status,
the generated-formula quality corpus with exact
text/JSON goldens against both installed artifacts, and the fixed
100-document/500-equation/500-reference workload under three seconds. It installs
the wheel and source distribution in separate clean venvs and runs CLI smoke for
each. A documented prerelease such as `v1.1.0rc1` is outside this stable publication
workflow and is not published by it.
The corpus contains 102 source equations with independently justified expectations, and the
100-equation accuracy gate also runs in ordinary PR CI. The exact release artifacts
must still pass their release-workflow checks; the timed performance gate remains
release-only.

Stable publication is additionally bound to the exact current protected `main` commit:
the stable tag must be immutable, and the workflow rechecks both remote SHAs after smoke
and immediately before publishing. The artifact download treats digest mismatches as
fatal, and both build and publish reject anything other than exactly one wheel and one
source distribution. Release tooling and smoke tests use the checked-in
`.github/release-constraints.txt` pins and record resolved dependency versions. The `pypi`
environment must require approval with administrator bypass disabled before a stable tag
is eligible for publication.

Deferred broader generated-document and project-mode behavior remains tracked in
open follow-up issues.
