# v1.1.0 release checklist

Use this checklist for the generated MyST/scientific-doc validation release.

## Completed release scope

- [x] MyST structure diagnostics for headings, fences, directives, roles, and
      code-cell metadata.
- [x] Heading hierarchy diagnostics for skipped levels and repeated top-level
      headings.
- [x] Generic MyST reference diagnostics for missing and ambiguous targets.
- [x] Generated-output anchor audit support for provenance-backed callers.
- [x] Notebook code-cell and recorded-output facts retain stable identities and
      exact JSON source spans without executing notebook code.
- [x] A committed notebook fact fixture and accuracy benchmark cover valid
      metadata, output MIME boundaries, profile diagnostics, and default silence.
- [x] Packaged `generated-myst` scanner preset and GitHub annotation workflow
      docs; provenance checks remain explicit already-loaded-document policy.
- [x] Opt-in `typst-portability` diagnostics for the focused Markdown and LaTeX
      display-math syntax baseline, with notebook cells explicitly excluded.
- [x] Typst portability good/bad fixtures, accuracy cases, and text/JSON/GitHub/SARIF
      golden outputs.
- [x] Fact-backed source-neutral cross-reference metadata and the `REF007` conflict
      contract, including built-in recorded notebook-output boundaries.

## Required checks

- [x] Focused MyST, reference fact/query/engine, generated-output, config, CLI,
      diagnostics, manifest, and reporter golden-output tests.
- [x] Focused Typst portability, fixture, accuracy, and reporter golden tests.
- [x] Full `pytest` suite.
- [x] `ruff format --check .` and `ruff check .`.
- [x] `python -m mkdocs build --strict`.
- [x] GitHub CI, Docs, CodeQL, and Scorecard checks on `main`.

## Stable-tag release gates

The release workflow also requires source, wheel, and tag version identity, at
least 100 globally unique documented equation fixtures executed through the
public analysis path, and the fixed 100-document/500-equation/500-reference
workload under three seconds.
These checks remain release-only and fail closed until their real evidence is
present.

Deferred broader generated-document and project-mode behavior remains tracked in
open follow-up issues.
