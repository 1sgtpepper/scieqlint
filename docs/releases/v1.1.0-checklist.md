# v1.1.0 release checklist

Use this checklist for the generated MyST/scientific-doc validation release.

## Completed release scope

- [x] MyST structure diagnostics for headings, fences, directives, roles, and
      code-cell metadata.
- [x] Heading hierarchy diagnostics for skipped levels and repeated top-level
      headings.
- [x] Generic MyST reference diagnostics for missing and ambiguous targets.
- [x] Generated-output anchor audit support for provenance-backed callers.
- [x] Packaged `generated-myst` preset and GitHub annotation workflow docs;
      the preset activates generated checks with the existing scientific checks.

## Required checks

- [x] Focused MyST, reference, generated-output, config, CLI, diagnostics, and
      manifest tests.
- [x] Full `pytest` suite.
- [x] `ruff format --check .` and `ruff check .`.
- [x] `python -m mkdocs build --strict`.
- [x] GitHub CI, Docs, CodeQL, and Scorecard checks on `main`.

## Stable-tag release gates

The release workflow also requires source, wheel, and tag version identity, at
least 100 globally unique documented equation fixtures executed through the
public analysis path, and the fixed 100-document/500-equation/500-reference
workload under three seconds.
These checks remain release-only and fail closed until their real evidence is
present.

Deferred broader generated-document and project-mode behavior remains tracked in
open follow-up issues.
