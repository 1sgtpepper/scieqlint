# Issue guide

Choose current work from the live queues:

- [Good first issues](https://github.com/1sgtpepper/scieqlint/issues?q=is%3Aopen%20is%3Aissue%20label%3A%22good%20first%20issue%22)
- [Good second issues](https://github.com/1sgtpepper/scieqlint/issues?q=is%3Aopen%20is%3Aissue%20label%3A%22good%20second%20issue%22)
- [Help wanted](https://github.com/1sgtpepper/scieqlint/issues?q=is%3Aopen%20is%3Aissue%20label%3A%22help%20wanted%22)

Search for duplicates and open a focused issue if no open issue fits.

Good issues include:

- duplicate search,
- security check,
- current `main` check,
- newest release check,
- exact command, input, and output,
- current and expected behavior,
- one focused request.

Bug reports missing a runnable reproduction, actual and expected behavior, or the
affected version or revision may be closed. Check bugs against current `main` and the
newest release, and search for duplicates before opening any issue. Feature, task, and
documentation issues do not need a reproduction; state the user need and expected
observable result.
